hi, my name is tyree milord and i grew up playing pokemon with my brother, and my love for the franchise has birthed into collecting the cards and playing the doubles metagame competitively.
a large part of building a team is knowing the calculations of your moves against some of the metagame staples, so ive made a primitive damage calculator, similar to the online pokemon showdown damage calculator.
i have went through the liberty of uploading all of the pokemon and moves via csv files, and adding it to a proper GUI for user usage. there are definitely a lot of missing components, like, the EV system, the IV system, held items, weather modifiers, terrains, et cetera but this serves to show how complex of a game pokemon can become, and how complex a calculator can really be.
the hardest part of this project was definitely debugging and finding the csv files--specifically the one with all of the moves on it. i had considered using an api, but i was up to my neck in ideas i wanted to include.
i also had a rough time adapting the code as the project went on. i wish i had a more concrete vision for the project from the beginning. it was definitely difficult, but it was fun watching my gui come into fruition.

the gui works as simply, pick a pokemon attacker, pick a pokemon defender, the levels are preset to fifty, if i do recall, and selecting a move. type effectivity is included. building a gui taught me about user interfaces, and how much care really goes into it. UX/UI designers deserve the world, that's one thing this project has taught me.
i had some issues with calculating stats after repeatedly using the calculator. i would have liked to iron out more of the issues, but for now, there is a reset button when the numbers start looking sort of janky.
